# Cirven 0.1.23 · 可选 VS Code 客户端

此扩展连接**本机正在运行的 Cirven 桌面 App**，复用原 OpenCode 会话、模型配置、任务、运行中指导及操作状态。它共用桌面运行时、模型登录和原会话。安装此 VSIX 不等于已经安装 Cirven。

从原会话点“打开任务文件”时，文本走 VS Code 编辑器，已登记的 Word 等文档交给系统应用打开。打开前核对当前保存版本。返回“已请求打开”后可到原软件确认文档已载入。

图标随宿主主题显示：编辑器入口分别提供深浅资源，侧栏容器由 VS Code 着色，聊天页标志直接继承当前前景色。

## 准备桌面 App

VSIX 只提供 VS Code 入口，还需要完整的 Cirven Windows 桌面安装包。内网使用组织提供的离线包；外网使用对应的完整分发包。先解压到本地目录，确认其中有 `START_EEAS.cmd`、`runtime` 和 `PACKAGE_MANIFEST.json`，再关联该目录。插件不下载或静默安装桌面程序。尚无安装包时请向提供插件的人索取匹配版本；不要把 VSIX 所在文件夹当作 App 安装目录。

桌面 App 的模型可选择 ChatGPT 账号登录或配置 API/内网模型。账号和密钥在桌面 App 配置，插件连接后直接使用同一份配置。

## 首次连接

1. 在 **Windows 本机 VS Code** 的扩展菜单选择“从 VSIX 安装”。测试时使用新的独立测试窗口和独立 `--user-data-dir` / `--extensions-dir`，保留原工作窗口。
2. 点击编辑器右上角 Cirven 图标，在右侧辅助栏打开对话，点击“关联桌面 App”，选择含 `START_EEAS.cmd` 的本地安装目录。也可运行命令“Cirven: 打开聊天”；不会占用左侧文件资源管理器。
3. App 未运行时点击“后台启动”，然后“连接”。首次连接仅提交一次配对请求，在 App 的受控对话框批准后自动加载；等待期间仅 GET，前四次间隔 1 秒、以后 2 秒，绝对截止 115 秒，无常驻空闲配对轮询。关闭视图或更换安装位置会中断等待，旧回执不覆盖新连接。发现文件和端口本身不代表授权。
4. 选择工程及已有原会话；消息直接回到该会话，执行期间的消息由原服务按实际状态作为指导接收。可选“计划 / 执行 / Workflow”（仅原会话已确认支持时可发起 Workflow）；请求停止仅表示已提交停止请求，需看原状态确认结束。

安装包 `PACKAGE_MANIFEST.json` 必须声明匹配的 `ide_companion` 能力标记（仅声明，非运行资格）；同时需要支持 `eeas.ide-companion.v1` 与 bootstrap `--electron --background` 的新版 Cirven。旧包、未运行、未配对、未配置模型分别提示；缺失 App 不会显示空白，也不会下载或静默安装。默认发现位置 `<安装目录>/user-data/ide-companion/discovery.json`；自定义 data-dir 仅通过应用级设置显式指定，不扫描用户磁盘。

## 中英界面

`eeasCompanion.language` 可选 `system`、`zh-CN`、`en`。默认跟随 VS Code 显示语言：中文使用简体中文，其他语言使用 English。侧栏切换立即生效，不重新配对、不清除草稿，也不翻译用户消息、文件名或模型回答。命令面板与设置说明使用 VS Code 原生 NLS，跟随 IDE 的显示语言；修改 IDE 显示语言时按 VS Code 提示重新加载其窗口。安装说明在英文侧栏中打开随包英文版本。

## 侧栏与主题

默认仅有一个右侧聊天视图。编辑器按钮只显示这份对话，不启动 App、不创建会话、不改变当前文件；仍可按 VS Code 的原生方式移动或收起视图。需要 VS Code 1.106 或更新版本。

未连接时显示本机依赖、关联安装目录和首次确认的引导，不显示空的消息输入区。已连接后按工程、原会话、消息与输入组织内容；连接提示、原工具状态和待核查结果分开显示，不把工具返回说成任务验证通过。

界面直接使用 VS Code 的背景、文字、控件、焦点和字体主题变量，随浅色、深色、高对比及自定义主题实时更新；不加载在线字体或外部界面资源。连接状态重复刷新时保留按钮与选择器，不反复重建当前入口。当前输入、IME、私稿 CAS 和编辑器焦点保留原有边界。

## 内容与连续性

桌面讨论的原回复可直接打开已登记的任务文本文件，或用 VS Code 原生 diff 查看同一原操作保存的完整修改预览。从 Cirven 打开已登记文件后，无需再在 VS Code 打开其目录。选中已保存正文后使用“选文”，填写意见并发送，会先保存精确反馈，再交给同一桌面 Agent 处理。引用默认收起为紧凑摘要；完整引文与“仅保存反馈”按需展开。此路径要求匹配桌面版本和各方法的单独授权，不从文件路径推断所属讨论。

模式与文字按同一个私稿版本保存，刷新、切换和恢复副本不会把 Workflow 默换为执行。模式未获当前原会话确认时保留选择与输入、禁止按该模式新发送；活动指导仍由原服务保持原任务的冻结模式，选择器提示此选择用于下一条新任务。原生页面类讨论不显示这项普通原 Agent 模式选择。

原话直接显示在聊天记录中，选句显示在输入区；打开文件和引用成功不额外常驻警告提示。

应用修改需先打开并保存原任务文件、查看对应预览，同一讨论中的同一已登记文件可继续用于反馈后的新预览，无需再打开一次，再明确勾选批准；不自动保存、替换或覆盖未保存编辑。选句保留 BOM、CRLF 与 Unicode 位置，文件变化、讨论变化或未保存内容会阻止后续提交。反馈或应用结果未知时保留原操作和草稿，只核查原请求；已应用预览不可重复应用。二进制与超过 192 KiB 的文本不进入此选句返工路径，其他原生文档仍由系统应用打开。

“改动文件”在所选原会话中按需展开，刷新只读同一工程、会话、代次与工作目录的记录。点击文件用 VS Code 原生 diff 打开不可变的只读历史文本，不用当前磁盘或未保存 buffer 补造历史。原“资料与工具 → 对比”仍单独比较已保存文件与当前编辑器。

标题明确区分“改动片段”和“完整文件”。原工具 patch 只有带原始行位置的片段，不代表整份文件或逐字节历史。完整文件必须由已授权的历史快照服务提供，且前后文本 UTF-8 SHA 均核对；客户端已支持此合同，但固定旧任务记录本身不产生完整快照。无数据、二进制、超界或证据不可用均如实显示，不提供接受、回退或写盘。

目录最多 128 文件，仅覆盖已保存的原根会话观察，不代表命令和子会话的全部改动。整个回复最多 512 KiB，单 patch 最多 128 KiB / 128 hunks。内存缓存最多 8 对快照 / 4 MiB，不落磁盘；切会话、代次或目录绑定后清空。失效引用拒绝读取，不把错误文本冒充代码。只在明确展开或刷新时读取，不后台轮询、不调用模型；需要匹配桌面版本及 `session.diff`、`session.diff.file` 的明确授权。

每个扩展激活实例的目录与正文读取合计单飞 1 个请求，跨会话切换也不叠加；无等待队列或自动补读。旧读取结束前显示读取状态，之后可显式刷新当前会话。缓存上限指插件自身，不声称回收 VS Code 已打开的只读编辑器；既有历史刷新独立保留。

完整文件保留原来源代次与精确来源作用域；工程、会话引用、目录绑定必须与当前所读对象一致，来源代次不得晚于当前代次，目录与正文的来源必须相同。旧来源在 diff 标题与文件提示中标为“历史版本”，不会说成新一轮已执行。旧片段缺少可证代次时不补造此字段。

- 侧栏显示原会话的安全有界历史、工具状态和待答/授权提醒。桌面投影最多保留最近80条消息、每条80个部分、合计64,000个正文字符，并受512 KiB整体回复上限进一步裁减。仅复用当前投影中未变化的消息DOM；移除消息或切换作用域、语言时释放旧复用记录，不另存Markdown解析缓存。待答/授权回复及新会话配置目前到 App 处理；子会话继续聊天未连接。
- 运行时仅刷新可见侧栏，闲置约 30 秒、执行中约 5 秒，单飞、失败退避；这些读取不调用模型。关闭扩展不停止桌面 App 或原任务。
- 私稿存于 VS Code `globalStorage` 下每次扩展激活独占的本地槽位，不跟其他窗口强同步。单槽最多 64 草稿、128 请求元数据及 1 MiB；最多 32 槽，满时明确报容量限制。不会自动删历史。旧槽可显式复制恢复，原槽保留；容量整理当前需用户先备份后清理已结束槽位，无自动归档器。
- 私稿按精确 project/session 引用隔离，局部 revision CAS 与精确私稿 ack 防旧回执清掉新文字；若回执清稿与新输入交错，输入原地保留并提示“保留输入并同步”，不偷偷覆盖。未同步文字另存此 Webview 的本地状态（64 项 / 1 MiB 上限），切换会话保留。**这不是跨窗口共享存储 CAS**。元数据先落盘后发；网络超时、断开或重启后不重发 POST，只核查原桥请求或原业务 operation。原 reply 不可取与原执行未知不是同义词，已观察的 RETURNED 事实保留。已知回执写盘失败时仅本实例内保留并提示，原 pending 仍阻止自动重发。
- “加入选文”仅在明确操作时读取当前可信本地工作区选文（最多 8000 字符），标出版本与是否未保存；不自动附全文。只读 diff 比较磁盘与当前 buffer（各最多 1 MiB），不保存、覆盖或编辑文件；Markdown 使用 VS Code 原生预览。
- 原回复中的明确 Markdown 文件链接、原 `file` 引用可直接点击：仅限该原会话绑定的工程目录，点击时由桌面 App 重新核对原消息与当前 FileSource。Word、Excel、PPT、PDF 等用系统应用打开；代码用 VS Code，Markdown 用原生预览，保留未保存缓冲区。注册制作插件的 PPTX 复用原产物 registry。目录外、远程、UNC/WSL 和无明确链接的文件名不会自动打开；不猜最近报告。旧 App 需配套桌面适配器更新。

## 边界

仅 Windows 本机 UI extension host + 可信 file 工作区；WSL、SSH、UNC、虚拟文件系统与远程工作区本轮拒绝，不复制目录共享。多根工作区最多 32 根。安装目录选在应用级设置，工作区不能通过配置悄悄选择可执行程序。

启动只运行已选安装包 `runtime/python/pythonw.exe`，固定 argv 为 `[-B, scripts/native_package_bootstrap.py, --electron, --background]`，`shell:false`，不拼 cmd/PowerShell 字符串。首次配对票据只有 VS Code SecretStorage；不读取 App DesktopToken、Cookie、Provider 密钥或第三方凭据。原请求记录不存消息正文或票据，私稿明确包含用户未发文字。发现文件不含授权秘密，重定向/未知 URL/任意 shell/命令 URI 均不接收。

Webview 使用 nonce CSP、`connect-src 'none'`、本地 media 范围及严格消息白名单；消息正文用 textContent 显示，不执行 HTML。切换会话不会抢编辑器焦点或保存 dirty 文件。后台启动成功只表示 spawn，连接就绪仍需真实握手。

## 本地桌面讨论

配合支持本地讨论接口的桌面版本，可在同一工程中读取和继续桌面讨论。运行中的指导与停止绑定原操作；结果未知时只核查原请求，不自动重发。旧连接需要显式更新授权后才读取新增讨论。

此通道包含消息、状态、指导和已登记文本文件的选句反馈、完整预览与明确批准应用。原任务会话的文件、只读差异和 Markdown 预览继续保留。任意软件与二进制文档的返工不属于该文本通道；未归属工程的旧讨论不会自动猜测归属。


恢复私稿会核对保存的工程与原会话并返回原工作；代次或引用需重核时保留原稿，不自动加载 Agent 或重发请求。

原生消息在持久接收后显示“原任务启动中”，同一对话等待回复；启动中可以请求停止，保留新输入并暂时禁用发送。待核查消息使用“核查结果”读取原操作；新格式请求核对完整输入身份后才清除未变的原稿，旧格式缺少该证据时继续保留原稿和未知状态，不重发。主动发送后跟随新回复，后台更新保留阅读位置；已应用预览只显示一次成功状态。

当前讨论只显示与它有关的待核查请求；其他讨论的数量放在按需展开的“本机私稿”中，切回原讨论核查，记录和原查询身份保留。旧请求缺少完整输入确认时，核查可以显示“已返回，原稿保留”，原稿和未知确认不自动改变。有现成命名信息的讨论沿用桌面名称，悬停可查完整名称；名称不改变原执行项目和文件权限。经验证的历史应用回执可直接显示“此预览上次已应用”，不会改写原回复或重新应用文件。新工作和切换讨论会结束前一条动作提示，真实错误与连接状态保留。

子任务记录中的“查看子任务改动”按需读取同一原子会话的历史差异，并复用只读原生 diff。子任务与根会话各自的快照引用绑定原会话、工作目录和子任务来源；可用完整文本保留经过校验的原写入账本引用。历史有缺口时明确显示部分覆盖，不补造命令改动，不用当前磁盘或未保存编辑补全。需要新增 `session.child.diff` / `session.child.diff.file` 配对授权；不后台读取、不新建 owner、不调用模型。此入口只读；应用、拒绝、回退及 dirty 编辑保护仍待实现和集中调试，源码接线不等于实际 VS Code/Windows 验收。

完整历史差异的“审阅”会另读当前保存版本并显示它是否仍等于原修改前/后；“接受此版本”“不采用此版本”只记录你对明确历史版本的意见。每条决定有独立原操作回执、完整请求摘要及审阅revision CAS；手工保存后旧准备不能直接发布。丢回执先查原操作，不自动再提交；原不可变决定可恢复自身回执，不用较新的意见替代。它不写工作文件、不启动/停止原Agent、不重跑工具或模型，也不等于实际恢复文件或当前任务整体验收。真正应用/回退和IDE未保存编辑保护仍在开发。需 `session.diff.prepare` / `session.diff.review` / `session.diff.review.operation` 单独配对授权，未获授权沿原入口重新配对。新用例仍待集中debug，未作原生资格声明。

现有完整文本文件可在“审阅”中选择“恢复修改前”或“应用修改后版本”：先取得同一原owner的持久交接，再沿Main首次明确授权的URI打开原文件，核父目录身份、保存SHA、buffer版本/hash/dirty后使用VS Code原生WorkspaceEdit。调用前先在同一私稿槽位保存操作意图，原生Undo由编辑器保留；不调用save、不reload，不写第二份文件。编码/BOM变化、混合换行、创建/删除、缺文件等尚未通过此文本路径，保持原稿，不从历史片段推测应用内容。

修改buffer并不代表保存。既有区域会显示“文件编辑待处理”，可打开原文件、核查原交接，或在用户自行保存/撤销后核对并继续；“保留当前保存稿”只在明确选择、clean编辑器和实际保存字节一致时结束本次交接。旧槽位恢复只读核查，不自动再次编辑；本机原扩展宿主和父进程未确认退出时，恢复副本不接管旧窗口的未决操作。各类UNKNOWN均不重放，父/子任务草稿保留。当前为源码实现和未运行用例，不是VSCode/Windows资格，创建删除及通用dirty权限联动继续开发。
