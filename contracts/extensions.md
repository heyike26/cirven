# 能力注册与升级吸收

能力记录：capability_id、adapter/provider、适用版本、supported/loaded/qualified 三个事实、测试证据、参数 schema、权限、来源、文件哈希。不要用 supported=true 一项代表已加载并可用。

公共接口保持小；原生扩展用命名空间和版本化输入保留增强能力。发现未知能力只记录，不自动提权或自动上线。未被测的能力不能由 LLM 自报合格。

插件按本地路径加载，核查运行时初始化信息及实际调用，不只看文件是否存在。[S02] SDK 默认配置与开发者 CLI 可能不同，记录实际加载源。

升级：获取/审查→候选快照→加载检查→新能力用例→旧用例回归→批准→稳定指针切换。正在运行任务固定旧快照；禁止共享可被自动更新的可变插件路径。需验证底座/插件不会绕过此快照自行升级；做不到则阻塞稳定切换。

E08 首次演练使用两版原创无危险操作的测试 Skill/插件：v1 可调用，v2 增加可观察格式；验证加载与行为改变，再退回 v1。它只证明吸收机制，不能冒充所有未来上游升级兼容。

回滚包括配置/数据兼容策略；schema 迁移前备份并验证恢复。旧程序不能盲读已不兼容的新数据库。保留变更与能力差异，不让平台自修改其正在运行的发布版本。
