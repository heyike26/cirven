# 工程工作流开发与验收

2026-11-26。优先完成本工作流的开发，再恢复原全功能目标的集中调试、竞品同任务对照和交付。Windows 普通本地 App 仍是交付平台。内网需要支持 Claude Code 和公司网关，现场连通由用户验证。开发、测试证据与发布状态分别登记在 state/SESSION.md。

## 在桌面使用工作流

1. 在左侧选定项目会话，直接点击标题栏的「工作流模式」。目录读取期间仍可阅读当前页，按 Esc 或当前选中的「日常模式」可以取消。若提示暂未打开，重新选择「工作流模式」即可重试。目录读取成功后，点击「默认」可以继续已有工作流，或创建自己的节点顺序。
2. 每个节点只处理本步交付物。宽窗可以边看目录边读详情，用「收起目录」给正文让出空间。查看依据、审核批注、笔记和设置都在独立浮层内，小窗从「本步工具」打开。技能、工具和 MCP 可分别展开。按 Esc 可以关闭面板并回到原入口。
3. 查看方案时可点带下划线的 OR 编号，直接定位需求。用「返回当前步骤」继续审核。审核通过后，界面等下一节点的独立会话读取完成再切换，阶段图标提示成功。系统开启减少动态效果时，图标直接显示结果。
4. 已有成果时，重新执行失败或需要澄清，可从标题右侧的状态打开「本步反馈」。在浮层内查看原执行记录、填写输入或进入阶段对话，Esc 返回原入口。等待执行和收到反馈时保留原成果、当前条目及阅读位置。首次执行的故障仍在页面直接显示。遇到「内核退出」时，点击「检查内核连接」核对该节点实际使用的内核、网关和模型设置，再重试本步。版本检查、切换和本地原厂程序导入都在「更新和切换版本」中。
5. 交付页可直接下载审核过的文件。审核通过后，从「交付凭证」核对范围，点「下载交付包」一次保存同一版本的获批文件和 JSON。ZIP 的 `files/` 保留成果目录，`receipt.json` 列出文件字节数、SHA-256、各阶段审核版本和通过的测试用例。也可单独下载文件或凭证。测试来源区分自动检查、人工实测和连接工具返回。收到或保存 ZIP 后，可在原审核的「交付凭证」里选择「核验本机 ZIP」，逐字节核对原样副本。历史交付仍可在原阶段会话打开、下载与核验。凭证 JSON 和交付 ZIP 每次下载都会重新核对原审核。依据会话仅归档时仍可核对。依据会话移出项目或删除后，下载完整交付包或凭证会提示依据不可读取。移回原项目后可重试，下载仍对应同一审批。要查执行经过或返工时间，打开「笔记与执行记录」。
6. 点击桌面悬浮球打开当前项目的阶段对话。每条成果右上角的圆形气泡可直接发起批注，也可选中文本或圈画。批注和对话共用浮层，打开或收起时保留正文的栏宽和阅读位置。保存后可直接带着这条批注继续提问，点「移除引用」回到阶段的一般问答。已发问题、回复和引用保存在左侧项目下的阶段会话中。发送补充要求后，展开「补充要求」，点「追问这条」即可带着原文咨询。收到处理回执后，同一条记录可展开「对应执行摘要」。执行期间发送的内容留在本步骤，当前执行结束后可选择「按补充要求执行」。待处理要求可以撤回。
7. 已审核页面的「创建修订」会先显示受影响的后续阶段。确认后可以从当前步骤重新运行，旧版本可通过同页的「查看此阶段上一版」打开。 本版生成成果后，点「对比上一版」可查看新增、修改、移除和共同条目的顺序变化，再点一项核对字段原值和新值。对比只读取持久成果，审批仍使用阶段页原入口。
8. 在需求梳理页选择「新增需求」并登记原话。系统分配独立来源编号。整理后的需求可在「查看需求原文」浮层核对。从原文、「补充要求」或包需求的「查看覆盖」入口，可以定位对应的包需求、验收用例和有回执的测试结果。审批前须覆盖每个有效来源，后续测试用例也须覆盖对应的 OR。
9. 阶段运行时可选「停止本次执行」并确认。已有文件和工具回执可从「查看本次记录」检查。历史文件按原执行回执下载，同名文件按各自版本区分。写入文件的原会话归档后仍可下载。原会话移出项目或删除时，工程总览与其他阶段的下载入口也会拒绝读取。移回原项目后可再次下载同一版本。阶段显示「执行中断」时，点「核查执行状态」读取原执行。核查与下载是只读操作。如果原操作只选了部分批注，关闭记录后可以点「重试原批注」。同一节点返工或修订后，继续使用的连接器若有结果未确认的历史调用，再次执行前会打开核对浮层。请先核对设备或服务状态，再决定继续。原执行回执可从原阶段的「笔记与执行记录」查看。
10. 如果原页提示「审核已保存」等状态，但目标阶段暂未打开，点击「打开已保存阶段」。此操作只核对并读取已保存的阶段。刷新后返回原会话仍可继续。
11. 测试用例可以同时定义自动检查与人工实测。测试页打开「人工实测」，对照已审核的操作和预期，登记实际环境、观察、通过或失败。设备未就绪时可记为受阻。返工后的新测试版本需重新登记，原记录可回查。
12. 在人工实测里打开「工位与固件」，可记录台架接线、上位机版本和多台设备的板卡、编号、连接及现场报告的固件版本。也可以关联本次测试读取的已审核开发文件，保存时固定原审批和文件摘要。同一测试阶段可从最近已保存的记录沿用工位。返工后，同一用例和实测动作如有原失败或受阻工位，可点「沿用返工前工位」带入设备、接线和上位机信息，本次固件、现场版本、观察和结论重新填写。原记录及文件仍从原测试结果查看。
13. 在人工实测里打开「实测证据」，可为当前动作选择串口日志、截图或采样数据，每次最多三个文件，合计 1 MiB。返回实测后继续填写，重载仍可恢复本机文件草稿。保存记录时一并固定原文件名、字节和摘要。需要复核时，在本次或原返工回执里点击文件名下载。
14. 在「返回开发返工」或开发页的「测试退回开发」里点「查看返工证据」，可按原用例和动作查看失败或受阻记录。人工实测可复核观察、工位及原附件，自动检查可查看原路径和退出码。关闭证据浮层后可继续当前任务。开发页引用触发本次返工的测试版本，后续复测记录保存在新的测试会话。
15. 新建运行采用逐项审核。方案树的三级叶节点覆盖所有已审需求，设计项必须引用覆盖它自身需求的具体三级方案。一个 OR 有多条通过标准时，测试用例必须逐条关联已列出的验收动作。审核待办会指出漏掉或错配的编号，重新运行会收到服务端核查的缺项。开发项至少要有其设计落点或已审构建输出的实际文件，功能行为继续由测试结果判定。
16. 执行期间可从「笔记与执行记录」打开「查看本次实时记录」。工具已经记录的路径、用例或设计编号按原发生时间显示，可展开查看写入前后版本、字节数和退出码。节点结束后可留在同一个操作记录中核对封存结果和下载原输出。
17. 「查看需求覆盖」可展开三级方案、详细设计和开发回执。相同编号的修订成果以各自的原审批及操作定位。开发关联可以显示已登记、待审核或缺少回执，行为是否核验通过在对应测试结果中查看。打开关联目标再返回时，保留已展开的阶段与上次选中的关联。
18. 新工作流使用容器验收时，在用例中审核命令、固定镜像和完整的预期文本，包含换行。执行时宿主核对实际捕获的标准输出及错误输出。即使退出码为 0，输出缺失、不符或被截断也不会通过。测试执行记录可查看退出码、预期和实际摘要、输出预览。
19. 新建默认工作流的详细设计读取已审用例。每条通过标准及已明确关联的用例动作都要进入相应设计项；正常、边界、异常和恢复场景按实际需要分类。打开「核对设计场景」可查看本版获准的触发条件、验收动作、输入与预期。
20. 支持标准输入的容器动作可登记一对正常与对照输入。两组输入及可观察结果须不同，宿主用同一条命令、同一镜像和同一输入文件清单各运行一次。正常和对照结果都符合已审预期后才通过。对照可约定应用退出码，124 至 127 保留给超时及执行器错误。执行记录显示两组输出、输入摘要和退出状态，返工时可查看原对照观察。
21. 直接验收开发产物时，容器用例可指定一个可直接启动的项目文件。宿主选取由已审开发项提交的确切字节，核对摘要后从只读挂载启动。执行记录可核对程序及开发审批，交付凭证会标明是否找到与被测程序字节一致的文件或包内成员。
22. 同一 OR 的多条通过标准须有可区分的验收观察。同一条标准的正常、边界、异常和恢复路径也须能分别核对。「审核待办」会列出重复观察的两个用例和动作编号。改名、改预期、只改容器超时，或对调同一组正常与对照输入，都会保留缺项。在动作中明确实际输入、观察目标或触发条件后，重新执行并提交审核。
23. 在任一当前阶段打开「覆盖总览」，按阶段筛选待核项，或按编号、名称搜索。点需求查看原始 UR、方案、设计、开发回执、用例及测试结果。打开某条证据后，选「返回需求覆盖」回到原阶段，再选「返回覆盖总览」恢复筛选、搜索和位置。返工后的旧结果可从历史会话核查；当前总览会显示需要重核的阶段。自定义流程按定义中实际连接的阶段检查，未配置下游的需求会单独提示。
24. v5 起，用例的「专项对应动作」列出各专项实际要执行的动作。启动与运行、布局、动效、交互、无障碍和硬件联动分开核对。文件校验可继续用于文件类需求。硬件联动应观察设备实际反馈或仪表读数，测试阶段须取得对应回执才可审批。已有流程按开始时固定的合同继续。
25. 新建流程使用 v6。硬件专项选择 MCP 时，在用例固定设备编号、编号字段、采样时间字段和读值字段。连接器应从所选设备取得本次读值及带时区的采样时间。宿主会拒绝错设备、缺字段或发生在本次请求窗口外的采样，即使读数相同。执行记录的「核对输入输出」可检查设备编号、采样及请求时间，来源标为连接器上报。返工保留原读回，交付凭证引用最终获审的本次读回。无对应接口或采样时钟无法校对的台架可继续登记人工实测。

## 用户路径与运行规则

在原左栏选择项目和会话，中心区切换日常或工作流。选择「默认」即可开始，也能新建、命名、排序节点和指定上游。每页呈现一个节点、补充输入、当前产物及页末审核。下一页仅在当前版本获审后开放。历史页可回看。工作流定义和运行实例分开，运行时固定定义版本；审核、批注与重试绑定产物和操作版本。模型可以提问，用户平时只需点击执行。

原阶段成为历史版本后，已有的本机文字草稿可从该版本的「查看本机草稿」取回。可复制补充或修订、批注、提问、笔记与返工原因，批注位置显示在类型旁。随后按需返回当前版本，并将原文粘贴到选定的输入框。取回时只读取原阶段的本机记录，当前草稿和原审核记录都保留。

每个节点有独立会话，输入仅包含本步说明、用户补充和明确选择的上游已审产物。把可见能力名单落实在内核进程和工具入口。模型提供文字、方案与推断；执行记录来自实际运行，交付链接对应保存的文件。阶段经验记录可提出新的 Skill、Tool、MCP，在用户配置后生效。

有经验或建议的阶段提供「经验与改进」。审核通过后，用户可选择原记录、目标节点和一项已登记的 Skill、Tool 或 MCP，审阅差异后保存。默认流程另存副本，自定义流程可基于当前定义追加版本或从原版另存副本。后续从流程库开始新运行时采用所选定义，已启动的运行继续使用原版本。原阶段会话内可查看保存记录，响应丢失时重开界面即可查询原操作。 在流程库打开「改进记录」可查这份定义的历史、所选版本的配置状态和对应的原审核原话。点「打开原阶段」可回到该次审核的会话，包括后来被修订的历史版本。

八阶段及自定义节点共用页面稳定性规则。已有页面可读时，等待目标数据期间保留当前正文、草稿及阅读位置。目标准备好后一次切换。工具浮层开关、提交批注和异步提醒应保留底层正文的几何及滚动位置。需要等待数据的浮层保持外框，读取完成后在内部更新。一个工作流弹窗内再开详情时沿用最外层的蒙层，背景亮度保持稳定，详情关闭后焦点回到原入口。输入错误或连接中断后，原页及草稿继续可用。宽窄窗口都检查打开、等待和关闭过程中的连续帧，以及键盘关闭后的回焦。审批动效集中在阶段标记上，正文不参与缩放或淡入。草稿未能保存时，提示留在当前编辑层。正文和工具浮层有固定的提示位置，悬浮对话的提示贴在外框下沿。输入值和焦点保持原位，存储恢复并成功保存后清除提示。

选择输出模板时，阶段表单保留原位置和已填写内容。读取替换文件期间，原模板仍显示在摘要上。只应用最后选择且读取成功的文件，失败后可以继续用原模板。点击「模板详情」可查看完整文件名、导出格式和错误原因，并可移除模板。上传连接在请求体完整前断开时，原模板与阶段状态保留，重新选择文件后可继续。

「内核与连接」底部显示读取、保存和刷新状态。切换 OpenCode 或 Claude Code 时，当前设置会话内的各自草稿保留。保存过程中可以继续编辑，回执只处理提交时的那一版。刷新发现已保存的连接被另一处修改后，在详情比较两份连接。选「保留当前草稿」后可显式再次保存，也可选「采用已保存连接」。

从窄窗的「本步工具」查看配置、依据、批注或执行记录时，在原浮层内切换内容。通过「返回本步工具」回到原工具项，按 Esc 关闭后回到页面的工具入口。从单次执行记录返回活动列表时恢复原日志条目的焦点和可见位置。查看详情期间新增的记录仍会显示，窗口变矮后原条目保持在浮层的可视区域。

失败卡片与执行详情按原执行显示内核和时间。保存下一次的内核配置时，原执行仍可按当时的身份核对。查不到可验证的旧内核时显示「原内核未记录」。

标题右侧的「审核待办」用于查看暂时无法审批的原因。明细在独立浮层内滚动，按 Esc 返回原状态入口。回执增加或解除待办时，阶段正文、对话入口和页尾审批区保持原位。

成果目录在宽窗保留自己的列位，长目录在内部滚动。窄窗以居中浮层打开目录，按 Esc 回到目录按钮，主动选择条目时聚焦该条目的标题。打开、搜索、收起目录或继续填写批注时，正文保留原宽度及滚动位置。此规则用于所有共用成果浏览组件的阶段。

续读位置随页面实际显示的成果版本保存。重新执行期间、失败后或待补充时，如果页面仍显示原成果，刷新或从阶段目录返回仍定位原条目和字段。打开新的成果版本时使用该版本的阅读位置。用户通过需求覆盖或批注明确指定目标时，优先定位所选目标。

在宽窄窗口间切换时，当前条目和筛选词随原阶段保留。缩放时如果键盘焦点在即将收起的目录内，焦点回到目录按钮。窄窗浮层只由当前操作打开，阅读书签只恢复原条目、字段和位置。

同一规则覆盖流程库、历史版本和需求覆盖。原文、未填写字段、模板文稿和模板填写内容在独立阅读浮层中显示。打开关联成果时保留来源，目标首次显示就定位并聚焦指定条目。从需求覆盖返回时恢复来源条目、原文浮层与各自的滚动位置。最后一步在原操作区反馈审核完成，继续保留交付页阅读位置。动效可用于状态图标、控件和浮层，正文容器始终保持可读，避免整页淡入、缩放或推移。

所有工作流页面上的后台刷新都应在原位更新。仍存在的可操作条目应保持 DOM 身份、键盘焦点及阅读位置，新状态在原区域显示。已经展开的输入区由用户收起，输入值清空或保存回执到达时也保持展开。验收同时观察正文、浮层内条目和实际焦点，覆盖执行中进度更新、宽窄窗口、主动返回和系统减少动态效果。

浏览已生成的阶段成果后，重新选择同一阶段或重开本机桌面会恢复原条目和阅读位置。宽窄窗口之间优先续读同一字段。新执行产生的成果使用新阅读位置，点击需求覆盖、来源或批注等定位入口时直接到该次所指定的条目。

同一个 Windows 用户从私有备份恢复到旁置安装时，桌面会随原项目恢复阶段草稿、浏览位置和待核查操作。用「核查原操作」读取对应回执，之后可在原阶段继续草稿。目标已有不同草稿时，由恢复器先停止导入并保留双方原文。

执行时的进度条以本步可核的开发项或测试用例为单位。开发项的完成回执应指向当前文件版本；有获审构建要求时，最新构建证据也须与构建时使用的源文件和输出一致。对应证据失效时计数会回退，重新取得当前版本的有效回执后恢复。一个用例的各项已审验收动作均有最新通过回执时，计为一个通过用例。进入审核后，开发和测试根据已审范围与结果核对显示完整计数。其他阶段在运行结束后显示当前状态，历史进度可从执行记录查看。

v7 新流程在「详细设计」为每项列出必交实现文件，用项目内的实际相对路径表示。只产出构建制品的设计项可以沿用已声明的构建输出。文件清单可从「查看文件」打开，长清单支持搜索。开发阶段须在设计项完成回执中逐一关联必交文件及构建输出的当前版本。遗漏或改动后沿用旧回执时，审核待办会定位设计项及问题。程序行为仍由测试阶段核验。已有 v1–v6 流程继续按其原合同运行。

v8 新流程配置有开发产物的容器启动与运行专项时，用例须填写 `subject_path`，设计须把该程序列入已审的必交路径或构建输出。正式测试从开发审批取出当前文件版本并直接运行，对照输入沿用同一已审程序。桌面实测和已获准的连接器仍可用于启动观察。v1–v7 已有运行按原合同续接。

自动文件检查核对实际目标路径和 SHA-256。容器测试核对整份输入清单。测试工作区覆盖已审核的被测文件时，当前通过不能用于审批，结果提示「需复测」，并可从标题的「审核待办」查看原因。需求覆盖按当前可核结果显示。原执行结论、文件摘要和已审核的历史版本保留。

交付审批读取每个成果物的实际字节。直接交付文件、ZIP 成员和嵌套 ZIP 成员与上游同路径文件对应时，摘要须与该已审或已测版本一致。新增独立文件可以随包交付。若出现版本冲突，「审核待办」会定位到具体文件或成员。新审核的 ZIP 在交付凭证中附成员路径、长度和摘要，旧版凭证沿用其获审时的字段。

在「交付凭证」中点「查看交付文件」，可以按路径或 SHA-256 摘要查找获批文件和压缩包成员。展开文件行可查看完整摘要，返回时回到凭证原入口。

工作流顶栏显示正在阅读的阶段及版本。查看历史成果时标记只读，左栏仍标记当前选中的会话。通过包需求、需求原文或补充要求打开覆盖关系时，「返回需求覆盖」会回到这次阅读的来源。关闭弹窗后可以从原按钮继续，展开的原文或补充记录仍可查看。

修订或返工前已发出的咨询仍归原阶段。打开原阶段的历史页时，可在原对话中看到迟到的回复。等待期间保留正文、选中条目、浮层和焦点。回复或中断结果确认后停止自动查询。

规划节点沿用本会话已审核的同输入成果时，可在提示旁点「核对原审批」。弹窗显示当时的审批时间、校验码和成果原文。源节点已经创建或审核了修订时，重复执行原输入仍可沿用可访问且未归档的原审批。输入、模板、上游、权限或内核与原版本不符时重新执行。复用成果仍须在本次运行中独立审核。关闭后回到当前成果和原按钮。

测试出现失败或受阻时，从「返回开发返工」查看可以返回的已审开发节点。展开范围可看待重新审核的阶段和关联用例。原因及所选目标按测试阶段会话保存在本机，重开 App 后可继续填写。确认后才写入返工记录并打开新的开发会话，独立开发分支继续保留原审批。

开始、审核、返工或修订提交后如果中断，可在原会话点「核查原操作」。确认已保存后，可打开该次操作产生的阶段。暂时查不到时，可用「按原请求重试」，系统沿用原编号和原参数。原阶段已换版时，点「查看原阶段」打开回执所指的只读历史页，之后可从「返回当前版本」继续。原阶段已删除或不可读取时，提示会说明原操作已保存及目标不可查看。

补充、修订和返工的成功回执只清理提交时对应的本机草稿版本。等待期间后来编辑的草稿按原阶段保存，即使文字与提交时相同。旧版待核查请求仍可核对原操作，缺少草稿版本标记时保留本机输入。

在流程库编辑自定义流程时，可以在保存期间继续填写。收到原提交的成功回执后，后续编辑仍留在表单，并以新版本为基础。结果未确认时，用「重试上次保存」恢复那次提交；确定发生并发版本冲突时，可将当前编辑转为副本，再显式保存。

## 实施顺序

1. 冻结节点协议与稳定编号，建立项目/会话归属、可编辑定义、运行快照、批注、持久审核和防止重复执行的操作记录。
2. 在原会话界面接入单节点页、折叠树、测试矩阵、模板、执行反馈与审核。保持左栏关联、日常草稿和桌面常用输入路径。
3. 在节点边界实施能力过滤；Claude Code / OpenCode 可切换，配置公司 API、子任务限额及独立更新/回退。复用工程内已有的内核、MCP 库、文件解析和认证 API。
4. 接入真实读写、测试回执和交付下载。上下位机与 Computer Use 使用显式选择的连接，记录所调用的接口及测量结果。远程工具自身的自报结果必须保留来源。
5. 功能接齐后按同一输入多轮、相同重试键、旧版本审批、跨项目访问、断开/重启、部分批注、窄屏、键盘及原生 Windows 流程调试；公司网络由用户现场验收。核对整个工具链与数据后更新发布包。

## 方案与上游依据

沿用 Cirven 现有 SQLite 和 FastAPI，避免引入第二份运行状态。LangGraph 开源实现的持久中断与恢复适合审查机制，其恢复语义要求副作用可重入；这里沿用原会话身份，并在内核调用前落盘占用操作。https://docs.langchain.com/oss/python/langgraph/interrupts

Claude Code 支持非交互输出、显式工具和 MCP 配置；内网接入使用兼容的 Anthropic Messages 网关、指定模型和凭据。OpenCode 复用现有程序和逐项权限，隔离配置/工作目录。两个内核独立记录版本、能力和失败。https://code.claude.com/docs/en/cli-reference · https://code.claude.com/docs/en/llm-gateway · https://opencode.ai/docs/permissions/ · https://github.com/anomalyco/opencode

MCP 采用已装的开源 Python SDK；用协议工具清单及调用结果连接能力。收录外接服务时标记服务来源，运行时只激活本节点选定的服务。https://github.com/modelcontextprotocol/python-sdk · https://modelcontextprotocol.io/specification/2025-11-25/server/tools

输出稳定性通过固定阶段说明、模板/输入版本、字段、排序、唯一编号、约束检查和版本回放衡量。固定输入重复执行的内容一致度与已存结果原样重开分别验证，模型未提供确定性保证时不承诺逐字相同。

## 使用与运行配置

在左栏选择项目会话，把标题栏「工作模式」切换为「工作流模式」，选择「默认」并开始。初始化填写项目背景、开发约束、编译环境和执行环境。点击「执行此步」生成产物，待澄清的问题在本步补充。圈画或选中文字后可逐条处理批注，或一次提交所有批注。页末审核会保存当前版本、激活下一页并在项目下建立独立会话。「本步配置」管理可见 Skill、工具、MCP、内核和本节点累计可调用的子 Agent 数量。工作流选择器支持新建方案、调整节点及显式上游，已有运行沿用开始时的定义。

「内核与连接」可为两个内核分别设置网关与模型。Claude Code 使用兼容 Anthropic Messages 的基础地址，OpenCode 使用兼容 Chat Completions 的 API 地址（常见路径为 /v1）。凭据栏填写由运行 Cirven 的进程继承的 CIRVEN_ 前缀环境变量名。启用公司内网策略后，新建默认工作流使用 Claude Code，执行层也检查此策略。公司现场需用自己的模型路由和凭据验证。内核支持检查官方版本、核对包摘要并安装，也支持导入已下载的原厂可执行程序及 SHA-256。保存多个版本后可切回此前已安装的版本。Windows 预览包随附 OpenCode，可从此处为工作流安装 Claude Code。

有外设的用例可选择已注册的 MCP，固定服务、工具、参数及要核对的返回字段。界面中的测试通过要匹配获审用例规定的每个检查动作。容器测试需设置 CIRVEN_WORKFLOW_CONTAINER_EXE 为 Docker/Podman 程序的绝对路径，CIRVEN_WORKFLOW_CONTAINER_IMAGE 为已在本机加载的 sha256 镜像 ID。容器检查读取本步获准的文件快照；构建项还需在获审设计中声明命令和成果路径。本地开发、文件检查及确定性 ZIP 可独立使用。远端设备是否执行成功以设备或仪表的观察为准。

在「查看本次记录」中可核对 MCP 的实际工具名称、时间和回复状态。写入调用记录后才向工具发出请求。断开时保留「结果未确认」，同一轮内相同未确认调用会被拦住。用于验收的调用如果成为最新的未确认记录，该动作需重新取得有效的通过回执；早先通过记录仍保留供核对。

同一阶段会话还选用了相关连接器时，从「重试本步」先查看待核对的工具、用例和时间。检查设备或服务的实际状态后，选择「已核对，继续执行」。按 Esc 或选「先去核对」回到原阶段。服务端将一次确认绑定当前版本和待核对回执，新执行仍可回看以前的未确认记录。遇到新的未确认调用时会再次提示。

结构化表格与节点树在桌面可直接查看。Word 和 Excel 模板可在可识别位置填写或重复简单表格行，保留原样式。PowerPoint 模板可在幻灯片文本框或表格单元格中用双花括号标记待填内容，例如“{{项目名称}}”。审核后下载演示文稿副本；未编辑的幻灯片、母版和媒体沿用原文件。可填写的 PDF 文本表单会保留原页面，按原字段检查必填、字数及换行。JSON 会校验字段顺序、层级和值类型，并允许按样例增加同类记录。CSV、TSV、Markdown 会核对列序或标题层级。静态 PDF 等只能稳定提取正文的版式会在上传后显示实际可下载的格式。纯规划节点在同一父会话、输入、模板、上游、能力与程序版本完全一致，且已有获审版本时可以复用。复用仍须独立审核；文件写入、测试和外设动作各自产生新的真实记录。
