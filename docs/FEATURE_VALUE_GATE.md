## 2026-10-19 补充：所有功能统一按用户工作验收

用户明确指出，截图批注、项目会话、工作台、重复入口和原始JSON只是暴露问题的例子；**本节适用于所有功能验收**，包括已有功能、新功能、前后端、插件、原生浮窗、VS Code、安装、离线交付和恢复。不能把这轮纠正降为几个界面的局部美化。

- **能集成的工作就集成**：以同一用户目标串起资料、选择、执行、结果与后续修改。优先沿用当前会话、对象、草稿和已确认配置；内部模块划分不能成为另开页面、重复选择或重复输入的理由。新页面或新入口必须有具体的任务、空间或权限依据；高级设置按需就地展开。
- **整合服从职责与信息架构**：集成不等于把所有功能塞进同一个菜单、弹层或聊天框。先明确导航、当前任务输入、对象管理和复杂工作区各自的职责与唯一入口；按用户所处工作决定展示位置，再精简步骤。用户同日指出：会话管理归左侧会话区域，输入区只处理当前对话；把整个管理页搬进输入弹层仍是职责混淆。类似问题须类推检查，不能只换容器就称完成整合。
- **最少必要交互**：记录实际点击、输入、页面/窗口切换、重复选择、重复确认和恢复动作。每个中间步骤要能解释它帮助用户完成什么；能由已有状态可靠确定的内容不再让用户填写。避免为了少一次点击而误选目标、带入别的会话权限、重放未知操作或覆盖手改。
- **干净、整洁、突出重点是独立指标**：用户同日补充，不能为了减少操作次数，把小选项全部堆到主界面。默认界面突出当前工作与主要动作；低频设置集中收纳，在具体情境下逐步展开。方案同时比较完成步骤、常驻控件与说明负担、主次阅读顺序和发现/纠错成本；为减少视觉负担而多一次合理展开可以更优，不只按点击数排胜负。实施时复用已适用的前端Skill及开发经验，实际检查宽窄中英和完整流程，不能只套样式。
- **显示用户需要的内容**：默认呈现可读正文、附件、产物、进展、必要范围、错误与下一步动作；内部JSON、协议字段、调试文件和执行回执不能充当产品内容，折进details仍不算完成产品表达。用户明确打开自己的JSON源文件属于文档阅读，和暴露内部载荷分开处理。
- **同一工作连续进行**：选择项目/会话、添加来源和反馈不应无故替换当前工作页面。工作台在当前任务确需文件、差异或任务图时适时展开；简单提问不强开，后台完成不抢导航与焦点。主页面、浮窗和IDE共享身份与状态，按各自空间组织交互。
- **视觉与交互共同验收**：检查实际排版、信息层级、唯一选中状态、动效全过程、有效裁剪、焦点、滚动、键盘与IME；还要覆盖打断、切换、迟回、失败及重启后的继续工作。接口成功、控件可点击、截图已生成，都只能证明各自范围。
- **所有页面的连续性**：打开、收起或提交批注、对话、补充要求和设置时，正文列宽、可见性、滚动位置保持稳定，关闭后回到触发控件。后台进度、回复和读取故障使用尺寸稳定的状态区或浮层，同一条目和控件保留原身份。用户主动展开、定位或导航时，页面随指定目标改变。异步导航先备齐目标，保留当前页面直到目标可显示。宽窗和窄窗在慢响应期间逐帧核对坐标与滚动，同时检查键盘回焦、草稿、长内容和系统减少动态效果设置。

每批在原验收记录中使用下方“工作验收记录”，不另造审批流程。**已知存在无必要切页、重复输入/入口、默认内部载荷、丢草稿或无法继续工作的受影响链，不能判为功能验收通过**；已通过的底层测试仍保留其原范围。历史记录不重写，既有功能按工作链补审并列出未覆盖项，不能宣称本规范落盘即全产品达标。

## 开发前：先还原工作，而非照单增加入口

每批新功能、修复、接入或维护记录以下六项，可在现有任务中简写，不强制新页面、问卷或全量重读。已明确的信息直接复用，只有会改变结果的歧义才问用户。

1. **目的与完成标准**：谁在什么任务/软件/阶段要得到什么可观察结果；功能想法只是候选手段。用实际环境与证据区分新建、存量接手、开发中、交付后和维护，不默认从零开始，见 [工程生命周期](ENGINEERING_LIFECYCLE.md)。不编效率提升数字。
2. **痛点与原因依据**：现路径在哪一步丢上下文、重复输入、切换、误改、等待或无法核验；记录事实、用户反馈、原因假设及尚未确定之处。解决表象之前检查共用状态、组件、权限或交接是否才是根因。
3. **可比备选与取舍**：主动发散相邻阻碍和可复用能力，比较真正会改变决定的可行做法；包括“不新增、沿用当前路径”和“复用已有入口或成熟能力”的基线，不机械凑三方案或限定方案数。用同一目的、输入与约束比较结果、步骤/切换、信息量、恢复、权限风险和资源总成本；说明为何选择、放弃或暂缓，不先拍板再补说辞，不以功能数量代替价值。
4. **前置与后置、最短路径与显隐**：串起触发前条件、用户与Agent操作、真实产物、检查/修改、继续或退出，列出最短必要操作路径。默认只直接呈现当前对象、主要动作和必要状态，说明哪些内容按需展开或仅在相关情境出现；错误、冲突和必要授权不能为简洁而藏掉。对象/版本/来源/权限须接续，已有草稿、人工编辑和后台工作须保护，不能只完成局部点击。
5. **场景与控制预算**：按下表逐类判断影响，选择必要正例/反例与恢复方式；不适用的类别写明理由，不把每个格子都变成新功能或新测试。记录本地/模型边界、共享预算、已知限制与待验资格。
6. **完整链实际对照**：从触发到结果检查、再反馈或恢复走通受影响链；条件允许时，以相同场景对照当前路径与有希望的备选，记录实际动作、信息可达性、错误/恢复和资源，而不只比较静态图。尚未实现的备选标为设计判断，不编造实测；绑定实际对象/操作/产物/依赖版本，验证关联反例及邻近行为。接口成功、模型结束、截图或按钮触发只证明各自范围，不能代替工作完成。

## 比较、验证与停止

在现有slice/任务/harness记录中保留简短的“目的与基线→备选及取舍→最短操作路径/信息显隐→实际对照与限制→决定及停止条件”，不另建平行流程，也不把这段说明塞进产品界面。出现取舍时比较多种做法；先用最小完整场景区分，依据真实问题继续修正、再比较，或决定沿用现状。明显被约束排除的方案记依据即可，不要求都实现一遍。

验证次数取决于变化与风险，不固定“三方案/三轮/每功能新增若干测试”。低风险改动复用仍适用证据，运行必要检查；并发、异步、未知结果、写入、权限或原生环境问题应补能区分原因的反例，并重复到关键结果可复现。没有新变化、失败或未决事实时不盲目扩大测试或模型调用。

开始前明确本批结果、不可牺牲的保护、比较依据和验证预算。主要目标达到、必要边界/恢复通过、无已知阻断且继续验证不会提供改变决定的新信息时收口；仍有未决风险则保留限制和后续节点，不能因预算耗尽就标完成。新证据推翻原因或选择时，只重开受影响的链，不抹掉旧失败，也不无限打磨无关细节。

## 场景发散与收敛

每批检查以下类别是否相关；按实际影响、已有证据和失败风险收敛，保留所选情境及不适用理由。无需为了“全方位”执行无关组合或反复验证未变依赖。

| 多窗口/多任务/多项目 | 并发实例、会话与子任务切换、迟到回复、重复触发、跨项目同名对象；准确归属，草稿/选择/结果不覆盖别人的状态，也不借其他任务权限。 |

| 资源与退出 | token、模型/RPC/工具调用、时间、磁盘/依赖、常驻owner/进程/内存、空闲唤醒；全链共享预算、释放自有资源，监测/恢复不暗自调用模型。 |

状态机、来源、授权和恢复应由同一权威对象承载；不为不同入口各造一份“已确认/已保存/已完成”。视图、草稿、历史观察、原执行状态与独立验收分别展示：恢复草稿不等于批准，模型返回不等于验证，取消请求不等于执行已停止。

操作步骤也是验收项：逐条记录触发到结果所需的点击、输入、切换和重复确认，删除没有必要的中间页与重复选择；复用当前工程、讨论、模型和已有授权。直接动作尽量一键完成，高级设置按需展开；来源变化、人工修改冲突或新增授权才增加相应核对。必要确认不能因少一步而省略，也不为展示“流程完整”强加确认。以真实交互计数证明改善，不预写节省百分比。

## 成熟产品与方案比较是交付门槛

每个新功能或成组交互修改，先留下三类可检查材料，再进入生产实现：

1. **成熟方案对照**：实际产品页面、官方说明或优质开源源码的精确位置；记录层级、默认动作、状态、作用范围和失败恢复。读取文档、查看截图、亲自操作分别标明；已有适用资料可引用，不能把“搜过”代替对照。
   用户2026-10-19再次明确每个功能先找范例：同批可以复用已核资料，但每项功能要能定位其对应范例、提取的做法、采用/不采用的原因；不能看过几个官网就替其余功能代签。步骤少须同时满足入口可预期、操作顺序合理和信息层级清楚。
2. **可操作比较**：同一任务、同一批真实数据、同尺寸下保留当前基线与至少两种真正不同的可行方案；比较查找、启停、配置、反馈和恢复的点击/输入/切换成本及信息密度。换色、换圆角不算不同方案。不把演示开关冒称真实后端可用。
3. **选定与验证**：写清选择及放弃原因，接入真实状态与持久化，检查成功/失败/未知/重启、宽窄和中英。界面已实现、真实交互已验、Windows已验分别记录；没有对应证据不得标为完成。只改文案或既有组件的低风险修正可复用该组件仍适用的上述依据，不另造无关页面或扩大测试。

功能合入与收尾记录必须能定位这三类材料。缺少对照或可操作比较的现有管理界面应补审；不以工作流文字存在代签已执行。任何开关要明确它控制的对象、范围、生效时机和真实观察；配置允许、连接成功、当前会话加载和实际调用不能互相替代。

## 必要复核与共享预算

- 默认先本地确定性检测、去重、精确引用、回执读取与影响集分析，零模型即可处理的事不送模型。保存、轮询、鼠标操作和状态刷新不自动触发模型；只有用户意图或相关任务确需判断时，才在既有授权和预算内调用原模型loop。
- 复核由相关变化或未决事实触发：内容/版本/绑定、权限、接口/依赖、模型能力、环境或验收条件确实影响本任务，已有失败/未知尚需查证时，才读取相应依赖和必要片段。未变且仍适用的证据复用，不全盘扫描、全历史搬运、逐保存重问或每批重审所有功能。写入前必要的本地CAS、当前权限与来源检查仍须执行，不能为省token省掉正确性。
- 主Agent、子Agent、总管、工具、检索、重试和后台扩展共用同一任务的预算与实际消耗记录；不得通过分层、拆会话或重试绕过总额。区分硬限额、软目标、估算与实际观测；尚无端到端硬限额就明确限制，不把某层计数冒充全体受控。
- 工程资源是每次实现的验收项：标明内存中队列、缓存、正文与并发上限及释放时机；磁盘的单件、会话及应用总量、预留空间、容量耗尽行为和可恢复清理；模型调用、上下文、输出、时限与重试预算。按需读取与按内容去重优先，关闭或切换对象后释放自有资源，不能用无限缓存换流畅。
- 额度显示区分模型实际usage、原生服务可观察计数和本地估算；订阅额度不可见时明确未知，不伪造余额或人民币费用。限额不能暗切API计费、另开子会话绕过或在UNKNOWN后重试。容量满时保留用户草稿、人工文件和未知操作，停止对应新增资源；清理提供可识别对象及影响，不擅删来源与恢复证据。
- 验证取正常任务、反复切换和满额/失败恢复的代表链，记录真实峰值/常驻内存、写盘增量、空闲唤醒及模型usage的可观察范围；接口限长不等于进程内存硬限额。新增组件先查是否已有全局配额，局部帽不能代签应用全局受控。
- 优先精确对象/版本及相关依赖，按需分页/选段，保留原件与覆盖信息；复用已确认选择和已读依据，避免重复说明、重复工具调用或重复模型上下文。内容节选不能隐瞒遗漏，旧来源不能暗换成latest。按成本和用户结果选择必要复核，不机械追求每步再确认。

## 实施中：动态工作流的调整规则

- 先完成批次的共用对象/交互/恢复契约，再按依赖分工；文件所有权明确，不能各自修一个入口形成不同规则。
- 发现新阻碍先判断根因是否属于共用组件、状态或交接；调整相关链与验收，再做一批修正。保持原目标和已确认边界，新增范围要有价值依据。
- 简单问答直接完成；专业方法按资料/约束/风险选择。工程类型不是固定流程，模板也不替代澄清与判断。
- 实施中发现新场景或失败时回到原因链，只更新受影响的方案、状态、依赖和验收；无关已通过项不反复读取或扩大测试。运行中指导、用户手改与后续维护也沿用同一门槛。
- 为当前任务选择后台、命令行、结构化接口或GUI；前台工作继续时，不因运行进展/完成自动抢焦点或打开工作台。
- 专业扩展按需启用，禁止为凑功能默认预装全部组件；实现实际新增的常驻owner、空闲唤醒、磁盘/依赖和上下文成本须进入共享预算记录。
- 用户在思考或执行中发送新指令是基础交互：输入可用，收件、原会话已观察、后续采用与停止分别有证据；不强迫先取消，不因活跃任务直接拒收纠正。不能把“已排队”显示成模型已经采用。
- 没有真实模型、设备、Windows或内网时只隔离相关资格；用原创夹具推进公共实现，失败原件保留，不用mock代签。

## 验收与退出

采用“用户工作完成”作为单位：能发起→交互→检查真实结果→继续反馈→取消/恢复，且当前软件、已输入内容与有效人工编辑得到保护。只有确实需要用户处理的项进入“待我处理”，工具/过程与证据进入同任务的“当前工作”。

交接分别列出：**设计风险/原因假设、已执行反例与原始结果、未覆盖情况及资格限制**。设计上想到不等于实际测过；夹具、原生Windows、订阅推理、公司模型和硬件资格分开。未通过的功能保留问题与证据，状态仍是待修/待验；不为结束批次标完成，不把新入口数量当进度。既有功能按影响逐链补审，不能声称本文件写完即全部体验达标。

验证与交付脚本也须核实际入口链：解析变量后的路径、调用目标、绑定版本和文件哈希逐项对应，默认 UNBOUND 成功不代表绑定后可执行。发现旧路径残留，保留原失败、仅修受影响引用，再用真实绑定验证；不重复构建或重跑无关已通过项。

## 完成一件事的交互成本

内部模块不等于用户入口。每批盘点重复入口、解释文字、原始结构展示与重复输入：优先并入已有会话、当前对象或统一管理器；正常路径只保用户下一步所需的信息。用户已说清的改动不再转抄到专用表单；从原消息绑定准确对象、原文和版本，在需要时提出一次有明确范围的授权，批准后走原执行链。授权草案、已批准、已开始和实际结果分别记录，不能用省步骤省掉目标核验。目录和产物应有适合内容的视图，JSON、内部指令与技术回执只在按需诊断中出现；不能用通用 JSON 页面冒作已完成交互。

用户进一步明确：**用尽可能少的步骤达到最好的结果；历史对话是工作导航的主体，文件管理服务于继续这段工作。** 每条完整链记录起点、预期结果、用户必需动作、窗口/页面切换、重复解释/复制路径、等待及失败恢复。减少步骤须保持结果正确、来源清楚、草稿/手改受保护且易于纠正；不能靠隐藏重要状态、误选上下文或取消必要判断换取更少点击。

交付物的内容、视觉和可编辑性也是完整结果。依[设计质量合同](DELIVERABLE_DESIGN_QUALITY.md)，短要求应复用已准模板/偏好与按需设计能力，只追问实质缺口；实际检查媒介的排版、交互与来源，不要求用户重复列设计术语，也不以导出成功代替美观验收。设计/制作/电脑操作通过可选插件或Skill接入，不默认把所有依赖并入本体。

新增客户端依[VS Code协作合同](VSCODE_COMPANION_EXTENSION.md)复用同一会话与执行权威；代码/diff/MD用IDE原生视图，Office用系统软件，继续保同任务和版本。缺桌面程序、未运行、未配对、版本或模型未配置分别有可操作入口；默认后台启动和主动唤醒分开。首版Windows本地优先，WSL兼容不绕路径守卫、不阻塞本地交付。

- 找历史后能直接续聊，保持原话题、草稿及可用上下文；不要先找文件、重选工程或听总管转述一遍。资料和产物围绕当前会话就地可达。
- 精确来源已经明确的普通问题不重复要求截图/选文件/填路径；多候选才原位询问必要差异，不默认猜最近。后台进展不抢用户当前软件。
- 回答中的产物可直接原生打开；反馈继续关联同一任务及新保存版本，避免下载、找目录、复制路径再解释。具体软件/版本未适配时如实说明覆盖，不能凭目标文案称已实现。
- 单项关联在当前对象附近管理；跨文件、多版本、任务图或集中审阅确需空间时才展开工作台。功能放在哪里取决于这一步完成什么，不为了填满工作台增加步骤。
- 反复使用相同已确认选项时复用选择，并保可见更正入口；自动动作有来源、可撤销，人工否决不被重加。首次使用、熟练使用、打断再回、失败重试分别检查。

步骤数和效率提升必须来自实际场景轨迹；设计预算只是待验证目标。除了正常最短路径，还需验证误选、迟到回复、原文件变化、切换任务及重启能否低成本恢复。保存/删除/授权等有实际后果的动作按现有范围处理，不机械追求所有行为一键完成。
