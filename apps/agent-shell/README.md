# EEAS AgentShell 0.1.0 — focused workbench

A Solid workspace with a project folder tree at left, a visual workbench in the center, and a persistent Agent conversation at right. Pane widths can be dragged or adjusted by keyboard, panes can be hidden/restored, and the entire workbench can fill the viewport with an Agent progress entry. Leaving fullscreen preserves the user's pane preferences, selected artifact and scroll position. Rich default motion remains interruptible and respects the operating system preference.

Runtime: serve `dist` at `/agent-shell/` with the same-origin EEAS API endpoints and an HTML fallback. JavaScript, CSS, fonts, WASM, grammar data, Word preview code and dependency notices are local assets. Runtime does not need node_modules, an internet CDN or the source staging tree.

MCP connection timeout is configurable from 100 to 120000 milliseconds; new configurations default to 60000 milliseconds to allow for cold startup. Saving a configuration or increasing its timeout does not establish a connection or prove that tools are loaded into an original session. Initialization, tool discovery and original-session loading remain separate observed states.

The original pinned OpenCode `AppInterface` is compiled as a lazy original-session entry. It mounts only when `/api/agent-shell/native?project_id=...` returns `READY` with a project-owned original server URL. `UNAVAILABLE` leaves the EEAS discovery workflow usable. Original OpenCode owns the model loop and OAuth; this UI build does not qualify a customer's provider, ChatGPT Pro/Codex subscription or Microsoft Office compatibility.

Choose a desktop folder, or enter an absolute path in web debugging, then read and materialize actual server-side files. Start with a problem, existing requirements, or a real task file. Problems and requirements can start without files; the task-file entrance requires a real material and explicit requirements acceptance before planning. Discovery revisions expose claims, gaps, questions, competitor evidence, next actions and graphs. Answers remain distinct from accepted answers and accepted assumptions. Only a ready, source-current session can create the downstream proposal. Draft Word reports and an independent pending file remain available while questions are unresolved. Explicit confirmation enables immutable harness Markdown export into the chosen writable folder. This workspace stops at harness generation.

Competition sources are explicit online single-page captures or existing offline materials. Coverage warnings, failures, byte receipts and the user-declared publisher kind remain visible; a capture joins the current material set only when the user chooses it. Reviewed template/writing profiles contain individually accepted source-bound rules. Word templates can be selected from a separate same-project readonly folder without changing the active folder or sending client file bytes.

Typed graph models render through Cytoscape with logical, hierarchy, mind-map, circular and bounded network layouts, pan/zoom/fit/search, node/edge details, source links and editing. Force layout is limited to 80 nodes; larger network views use a bounded circular layout. Rectangle annotations derive their affected nodes from actual rendered bounding boxes. Freehand nodes remain explicit user choices. An annotation can be added to the conversation draft without clearing existing text, or sent directly. Multiple draft attachments are submitted through a single bounded original OpenCode advance. Recording an annotation alone never calls a model.

Actual DOCX bytes render through pinned `docx-preview` in a same-origin sandbox with scripts and network disabled. Byte SHA is checked first. Generated report text selections use the actual OOXML paragraph map and Unicode codepoint offsets; repeated matches require a context choice. Unlocatable text remains a visible limitation. The preview preserves source bytes and does not claim Microsoft Word layout fidelity.

Local OCR runs only through the configured CPU component and exact registered image/frame API. Actual decoded-image pixel polygons and recognition confidence remain visible as observations requiring user review. Selecting recognized text attaches its immutable OCR line locator, observation reference and bitmap reference together. Saved references reload through the real server rather than trusting cached text. Recording or recognizing alone does not call an LLM.

The desktop bridge supports `eeasDesktop` version 1 folder/file pickers and native document open/attach/resize/detach/capture calls. A compatible original `window.api` picker can also be used. Native document viewing is offered only for actual `IMPLEMENTED_NOT_QUALIFIED` Windows capabilities; browser/Linux `UNAVAILABLE` is explicit. Editing uses a native child window; annotation viewing detaches it and shows the source-bound captured PNG. Frame or local-file annotations retain an exact bitmap reference, never a fabricated graph-node reference. The provider image-support checkbox is a user declaration, not a verified model capability. Paid/company vision, offline OCR and Windows application compatibility have separate qualification scopes.

Build uses the archived selected OpenCode source at commit `733b2c627e5aec39cb33cc22373bdce33053ef2c`, Ghostty-Web at `83c0a07b8628b748aed073b232cb4b52a6ca11c1`, docx-preview 0.4.1 source at `c533f383069008d4a1e05c6171ef8777fd078385`, the lockfile, recorded npm cache and Node 22.22.2. Restore the selected source archives and manifests so `staging-native-ui` is next to `apps`, then run from this directory:

```sh
node scripts/build.mjs
node scripts/typecheck.mjs
node --test tests/*.test.mjs
```

Before build, every selected upstream source byte is checked against `source-manifest.json`. Temporary local module links and original fonts are prepared without editing upstream source. The fixed OpenCode commit declares an `@pierre/trees@1.0.0-beta.4` expansion-event patch in its Bun lockfile. EEAS restores that exact four-file runtime/type patch during installation, build and typecheck; original patch bytes, source URL, commit, and before/after SHA-256 are recorded in `patches/pierre-trees-manifest.json` and included in `dist/licenses/upstream-patches`. Unknown installed bytes fail before any patch write. The prior two directory-picker diagnostics and missing runtime callback are retained as historical evidence; current typecheck requires the full compiler exit to be zero, including upstream sources.

Evidence is listed in the delivery manifest: 42 independent non-GUI contracts tests (including six OCR counters and three draft restore counters), 14 discovery HTTP checks and the separate actual local CPU OCR HTTP probe covering CAS, exact sources, Word/diagrams, feedback, restart and source drift. The HTTP probe uses one configured model protocol fixture, not a paid model. Original AppInterface plus the full new workbench is actually built. Fresh cache-only install and runtime-byte comparison are recorded separately. Browser layout, keyboard, 200% zoom, native pickers and Windows offline qualification require the root agent's actual GUI/runtime evidence.

Original source/license notices and actual installed dependency metadata are in `public/licenses`, copied into `dist/licenses`. Delivery separates curated source/runtime bytes from verification and build archives. Do not copy probe databases, access tokens, node_modules, npm-cache trees or whole staging directories into the application.
