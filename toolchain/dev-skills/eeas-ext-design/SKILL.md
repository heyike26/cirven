# eeas-ext-design

每项功能先查成熟产品/优质开源/官方资料，提出有实质差异的可行方案作交互与显示对照，选定后完整验证美感与顺畅性；同批相关功能可复用已核来源，不逐按钮盲搜。

只回答当前切片的阻塞设计问题；先读实际代码，查对应公开接口。依docs/FEATURE_VALUE_GATE.md比较真正影响决定的备选与当前基线，选择最小完整场景对照；不固定方案数或验证轮数。
每个功能先按docs/FEATURE_VALUE_GATE.md明确目的/实际阻碍/完整相邻过程/完成标准，主动发现问题；用户明确要求研究先齐时，先完成批次资料与共同交互/恢复设计，不能见一点进展就逐按钮开发。
优先成熟能力、单一职责、可离线获得；禁止为未来所有情况提前设计框架。原生增强保留，安全和证据不透传给模型决定。
形成一条 ADR：问题、决定、证据、替代、回退。达到用户指定研究门槛后转build按完整场景批量实现，设计不能取代功能。
