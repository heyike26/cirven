# 拆解通用项目并形成交互网络

从实际资料和已确认回答推导任务，不按项目类型套工具预设。使用PlanningCandidate schema，每节点包含目标、依赖、输入、交付物、验收、风险与能力需求。调用validate_network和acceptance_coverage核结构。模型建议与来源事实分开。缺能力提出优质OSS候选方案；计划确认不批准工具执行。

已有工程优先拆当前增量与影响范围，保留已完成成果、人工修改和不相关任务，不重建整份初始计划。按实际需要衔接基线核查、诊断/实现、相关回归、目标验收、交付/恢复和维护记录；未知基线与旧故障单列。已发布版和在研版并存时分别绑定版本，不把一边的结果代签另一边。

内容结构参考随附 GitHub Spec Kit v1.1.3（MIT），EEAS 共创与来源规则优先。模板只读取，不启动上游 hooks/CLI。
